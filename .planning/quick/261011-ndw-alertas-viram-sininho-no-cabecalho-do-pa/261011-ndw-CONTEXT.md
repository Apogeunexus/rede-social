# Quick 261011-ndw: alerts become a bell in the panel header

Follow-up to quick 261011-jqy and 261011-l72 (dev-only `/painel-preview/<nivel>`, branch `feat/painel-preview`, iPhone 17 Pro Max mockup from `lg`, container queries `@3xl`). Same constraints: catalog-only strings (pt-BR), no hex in `.tsx`, tokens only, vertical scroll only, dev-only route gate untouched, Biome/boundaries/literal guard green.

## Locked decisions (user, 2026-10-11)

1. **The alert lists leave the panel body.** Today the "Atenção" section (level 1 `PlatformOwnerPanel`, level 5 `TenantAdminPanel`) and the "Pendências" section (level 2 `PlatformAdminPanel`) render an `AttentionList` inline, between the header and the KPIs, and the user finds that it clutters the view. Remove those inline sections.
2. **A bell in the panel header instead.** In `PanelHeader` (top row, beside the period pill on the right), levels 1, 2 and 5 show a bell button (lucide `Bell`) with a count badge (the existing `Badge`/`IconButton` from `@rede-social/ui` if they fit). Its accessible name says what it is and how many ("Alertas, 3"), from the catalog. The badge uses the danger tone when any alert is `danger`, otherwise a neutral/brand tone; status is never colour-only (the count is text).
3. **Tapping the bell shows all the alerts.** A dropdown panel anchored under the bell, inside the panel's own box, listing every alert with the same content as today (tone label icon+text, title, detail) — reuse `AttentionList` (or its row markup) inside the dropdown. Title "Alertas (N)" (level 2 keeps its wording "Pendências (N)" if clearer — planner's call, one consistent pattern). It must stay INSIDE the iPhone screen when framed (absolute positioning inside the header/panel, not a portal, not the top-layer `popover` API, not `position: fixed`, which would escape or misbehave under the frame's CSS transform) and work full-width below `lg`. Max height with its own vertical scroll if long; width fits the 408 px framed content area with no horizontal overflow.
4. **Behaviour**: button has `aria-expanded`/`aria-controls`; closes on Escape (focus back to the bell), on a click/tap outside, and on toggling the bell again; focus is visible. This needs a small client component (`'use client'`) — keep it in `apps/web/components/dashboard/` (or the module `ui/` if it stays string-free and host-driven); server panels pass already-translated data to it. Levels without alerts (3, 4, 6, 7) show no bell.
5. Remove now-unused catalog keys/props/code (no dead strings). Keep everything else (KPIs, charts, tables, other sections) unchanged.
