# Quick 261011-jqy: Painéis por nível de acesso (pré-visualização com dados de exemplo)

## Locked decisions (user, 2026-10-11)

1. **Example data first.** The 7 panels render FICTIONAL fixture data only. No API route, no DB query, no migration. Real data is wired later, panel by panel.
2. **Lives in the project, in the app's own stack and conventions.** A new module package `packages/modules/dashboard` (`@rede-social/module-dashboard`, same layout as the other modules: `package.json` exports, `ui/`, fixtures, tests, `README.md`) holding presentational components + fixtures; the page that renders them lives in `apps/web`. Follow `apps/web/CLAUDE.md`/`AGENTS.md`, Biome, the boundary rules (`pnpm boundaries`), and the UI literal guard (`scripts/check-ui-literals.sh`): every user-facing string goes in a new `apps/web/messages/pt-BR/dashboard.json` catalog (correct pt-BR accents), and NO colour literal in any `.tsx`.
3. **Vertical scroll only.** KPI cards are a wrapping grid (2 columns on phone, more on wider screens). No carousel, no `overflow-x` row, no horizontal scrolling anywhere on the page at 360–430 px wide. Tables that do not fit on phone become stacked card lists (the `TenantTable` pattern: table from `md`, cards below), not a horizontally scrolling table.
4. **Tenant visual identity = Igor Alves.** Colours come only from the existing tenant tokens (`bg-brand`, `text-brand`, `bg-card`, `text-text-secondary`, `--color-success/warning/danger`…, see `packages/ui/src/styles/tokens.css`). The preview applies the Igor Alves tenant branding through the SAME runtime mechanism the app uses for a real tenant (the brand variables on the shell root), fed by a fixture branding record: primary `#2e6fd0`, secondary `#5b9cf8`, dark primary `#5b9cf8`, display name "Dr. Igor Alves", Manrope (already the app font). The hex values live only in that fixture/data file (a `.ts` data record, like a tenant row), never in `.tsx`. Find how `(app)/layout.tsx`/`AppShell` inject `--brand-primary` etc. and reuse it instead of inventing a parallel mechanism.
5. **Preview route must not exist in production.** Something like `apps/web/app/painel-preview/[nivel]/page.tsx` (or one page with a level switcher). It renders without a session and without the API. In production it must 404 (`notFound()` when `process.env.NODE_ENV === 'production'` or an explicit opt-in env flag). If `proxy.ts` blocks unauthenticated paths, add the preview path to its public list ONLY outside production, with a test in `proxy.test.ts` proving production still blocks it. Do not weaken any other auth/tenant check.
6. **Look like the app.** Reuse `@rede-social/ui` primitives (`Card`, `StatusPill`, `SectionTitle`, `Chip`, `SegmentedControl`/`Tabs`, `Badge`, `EmptyState`, `Skeleton`) and lucide icons; status always icon + text (never colour alone — warning orange and danger red are near-identical for deutan colour blindness). Charts: plain SVG/CSS components in the module (no chart library is installed; do not add one), drawn to scale, colours from tokens (series = brand, previous period = `text-tertiary` dashed).
7. Mark the page visibly as example data ("Dados de exemplo") so nobody mistakes it for real metrics.

## The 7 panels (content spec)

The full visual reference is `reference-prototype.html` in this folder (open it in a browser; switch "Celular/Computador"). Port its content and hierarchy, not its CSS. Summary per panel — question it answers, then blocks in reading order:

1. **Dono da plataforma** (`platform_owner`) — "A base de clientes está crescendo e usando o produto, e o custo cabe no plano?" KPIs: clientes ativos (+sparkline 12m), novos clientes, membros na base (% que interagiram 30d), armazenamento (de 1 GB), receita mensal = "Ainda não medido" placeholder card. Atenção (armazenamento 84%, 1 cliente em risco). Linha 12 meses clientes ativos. Barras "Membros por cliente" (concentração). Barras "Adoção de módulos". Lista/tabela de clientes, piores primeiro.
2. **Admin da plataforma** (`platform_admin`) — "Qual cliente está travado ou quebrado agora?" Pendências com prazo NO TOPO (domínio expirado/36h, convite 4 dias, falhas de mídia). KPIs: domínios não verificados, convites sem aceite, clientes sem dono, falhas de mídia 24h, push com falha. Funil de ativação (barras horizontais com % entre etapas). Falhas 24h por cliente.
3. **Suporte da plataforma** (`platform_support`) — "O que está acontecendo com este cliente, sem ver conteúdo?" Busca de cliente; faixa "Acesso registrado · motivo"; KPIs (domínio principal com status, membros/bloqueados, erros 24h, última atividade); configuração (recolhível); erros 24h (lista); botões "Escalar para admin" e "Meus acessos registrados". Read-only.
4. **Dono do cliente** (`tenant_owner`) — "A comunidade cresce, retém e dá retorno?" KPIs: membros, membros que interagiram (sparkline), retenção de novos, comparecimento em eventos, valor de pedidos ("valor registrado, sem pagamento real"). Linha 12 semanas com período anterior tracejado. Barras "Onde os membros interagem". Mapa de calor de coortes (on phone: a single number card). Conta (recolhível).
5. **Admin do cliente** (`tenant_admin`) — "O que precisa de mim hoje e o que funcionou?" Atenção NO TOPO (conversas aguardando 26h, evento hoje 92/100, story expira 5h). KPIs: aguardando resposta, 1ª resposta (mediana), membros que interagiram, novos membros, interações por post, pedidos. Posts que mais renderam. Seções recolhíveis: eventos (comparecimento), comunidades, loja, moderação.
6. **Equipe do cliente** (`tenant_staff`) — "O que da minha função está esperando por mim?" One block per granted function (atendimento, moderação, conteúdo, loja); with 2+ functions, tabs with a count badge; with none, an empty state. The preview offers a control to simulate which functions the person has.
7. **Membro** (`member`) — "O que não posso perder?" Not a new page in the real app: a "Para você" block at the top of the profile with up to 3 action cards (próximo evento + "Fazer check-in" + "Começa em 40 min"; "O suporte respondeu" with unread dot; "Comunidade VIP liberada pela sua compra"). Each card hides when empty.

Each panel also shows, in the preview chrome only, its availability status ("Dá para fazer hoje" / "Parcial" / "Bloqueado" / "Depende dos níveis novos") and "O que falta no app" bullets, exactly as in the reference.

## Out of scope

API, DB, migrations, the 7-role model in the database, real metrics, navigation entries in the real app menus, changes to existing screens.

## Verification the executor must run (project Definition of Done)

`pnpm lint` (includes the UI literal guard), `pnpm typecheck`, the module's and `apps/web` unit tests, `pnpm boundaries`, and a Playwright or manual check at 390 px that `document.scrollingElement.scrollWidth <= clientWidth` on every panel (no horizontal scroll). Supabase/Docker is NOT available on this machine: the preview must work with `pnpm --filter @rede-social/web dev` alone (no API, no DB); say so if any env var is required and give it a safe local default.
