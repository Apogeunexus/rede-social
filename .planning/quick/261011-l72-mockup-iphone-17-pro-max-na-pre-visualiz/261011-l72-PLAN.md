Recorded planner choices (Claude's discretion, each applied in the task named):
- Container variant `@3xl:` instead of a literal rename to `@md:` (D-04 names `@md:`/`@lg:` only as examples). In Tailwind 4.3.3 the container sizes differ from the viewport breakpoints with the same name: `node_modules/.pnpm/tailwindcss@4.3.3/node_modules/tailwindcss/theme.css:328` has `--breakpoint-md: 48rem`, but `:337` has `--container-md: 28rem` and `:341` has `--container-3xl: 48rem`. `@3xl` keeps the 48rem threshold the old `md` used. Unframed, the container is the page content box (window minus 2rem), so the switch moves from a 768 px window to an 800 px window. That is the only change below `lg`. A literal `@md` would switch at a 448 px container, only 8 px above the frame's 408 px content width, and it would also show the desktop table on 480–767 px windows that show cards today. This choice must be named in the SUMMARY.
- The new component does not reuse `components/platform/preview/DevicePhone.tsx`. That component is `'use client'`, models a 393x852 iPhone 15 Pro, hard-codes its clock and wraps the device in `role="img"`, which would remove the panel's headings, tables and buttons from the accessibility tree and from the role-based e2e locators. Changing it would also touch the platform panel, which is a non-dashboard screen (D-04). The new component reuses its tokens (`--device-bezel`, `--device-rim`, `--device-shadow` in `packages/ui/src/styles/tokens.css:620-624`), its Dynamic Island and home-indicator proportions, and its pattern of a transform scale over a reserved box (DevicePhone.tsx:82-101).
- The level name stays as a visually hidden `h2` in PreviewChrome, in the same DOM position as the removed card's `h2`. Without it the panels' `h3` sections would sit under the nav's group headings.
