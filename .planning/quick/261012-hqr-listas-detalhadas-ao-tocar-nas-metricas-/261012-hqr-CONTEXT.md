## Locked decisions (user, 2026-10-12)

- D-01 **Tapping a metric opens its list.** In "Sua atividade", these cards become navigable: Curtidas, Comentários, Salvamentos, Compartilhamentos, Posts vistos, Vídeos e reels (count + time cards both open the same list), Stories vistos. (Tempo de uso, Onde você mais participa and Presença stay as they are.)
- D-02 **Pattern = a list screen with "Voltar".** Server-rendered, no client JS needed: each card is a real link to the same route with a query param (e.g. `/painel-preview/membro?lista=curtidas`, allow-listed values only — anything else falls back to the report, like the staff simulator's `parseStaffFunctions`). The list screen replaces the report body inside the panel (the profile header may stay), with a visible "Voltar" link back to the report, a title, the period pill ("Últimos 7 dias"), the item count, and an "exemplo" pill when the list's data has no source today. Inside the iPhone mockup the list scrolls vertically within the screen. Keyboard/focus: links focusable, focus ring visible. Cards that are links must look tappable (chevron or "Ver lista" affordance) — only these cards, nothing else gains a chevron (earlier review: no chevrons that lead nowhere).
- D-03 **List contents** (fixtures, deterministic, internally consistent with the report numbers):
  - **Curtidas (46, exists: feed_likes)** — posts the member liked: post excerpt/title, community, when liked (relative date), newest first.
  - **Comentários (12, exists: feed_comments)** — the member's own comments: comment text, on which post (excerpt), community, when.
  - **Salvamentos (9, exemplo)** — saved posts: excerpt, community, when saved.
  - **Compartilhamentos (3, exemplo)** — shared posts: excerpt, how (link copiado / compartilhamento nativo), when.
  - **Posts vistos (exemplo)** — the KPI changes to "60 posts" with note "128 visualizações": list of all 60 unique posts, sorted by times viewed desc then most recent, each row "vista N×" (counts sum to 128) and when last seen. 60 rows is fine (vertical scroll); generate them deterministically in the fixture (a small pure builder with a fixed seed/table is OK) — no randomness at runtime.
  - **Vídeos e reels (exemplo)** — 41 assistidos, 1 h 12 min total: each video/reel with its duration, time watched by the member and times watched ("2 min 10 s de 4 min 12 s · 2×"); watched times sum to 72 min; count = 41.
  - **Stories vistos (23, exists: the member's own story_views — but time per story does NOT exist)** — each story: author/community, when; time viewed per story ("12 s") is example data → per-row time carries the "exemplo" marker (or the list header explains time is exemplo while the list itself is real — pick one consistent rule and state it in the SUMMARY).
- D-04 Fixture types: reuse/extend `ReportValue<T>` so each list is typed measured vs example; helpers for sums (views total, watched minutes) with unit tests proving: likes list length = 46, comments = 12, saves = 9, shares = 3, posts viewed = 60 rows summing to 128 views, videos = 41 rows summing to 72 min, stories = 23 rows.
- D-05 Post excerpts must look like the Igor Alves community content already in the fixtures (consistent tone/communities: Comunidade VIP, Geral, Eventos). No other member's name appears anywhere in these lists (author is always the tenant/creator "Dr. Igor Alves" or the community).
